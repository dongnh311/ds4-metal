- [x] Item 1.7 (spec §25): verify bundle size vs cache-plan per-expert size — **VERIFIED,
      no size bug**. ds4_ssd_auto_cache_plan's per_expert_bytes is computed by
      streaming_layer_routed_expert_bytes (ds4.c) = gate+up+down = 422400+422400+645120
      = 1489920 B (1.4209 MiB), byte-exact with qwen38-experts.index.json's recorded
      per-expert size (pager startup log: "1489920 B/expert (1.4209 MiB)"). The old
      "1.42 MiB vs ~2 MB -> ~58 GiB shortfall -> swap" hypothesis is DISPROVEN (it
      predated the Bug 1 bundle rebuild). Two real secondary findings, feeding item
      1.4, NOT a plan size bug:
        (a) ds4_expert_pager.c sizes the slot-index array by max_bundle (645120,
            the down tensor) -> slots = budget/645120 = 8087; since gate/up bundles
            are smaller (422400) and the byte budget is enforced separately on live
            bytes (pager_reserve_slot), the slot COUNT can bind before the byte
            budget, leaving ~20% of the 4.86 GiB budget unusable. Candidate 1.4 fix:
            size the array by the smallest bundle (or bundles_count) so the byte
            budget is the sole constraint.
        (b) The dominant read-GB driver is simply cache (4.86 GiB) << working set:
            a 512-token prefill touches most of the 34.31 GiB bundle across 48
            layers, so most accesses miss and re-read regardless of slot accounting.
            This is the ground-rule-4 over-budget signal (15.6 GiB read vs ~1.73 GiB
            budget at default chunk) and is a cache-sizing/prefetch question for
            items 1.2/1.4, not a correctness or plan-size bug.
      Swap growth is OS file-cache pressure (147 GB model mmap + bundle pread), not a
      cache-plan RAM over-allocation (the pager stays within cache_budget_bytes).
- [x] **Pager eviction memory leak fixed (user-approved out-of-order memory fix)** —
      `ds4_expert_pager.c pager_evict_slot` decremented all cache accounting but
      never `free(cache_data[slot])`, so every eviction leaked one expert bundle
      (~0.4-0.6 MiB). On a cache-thrashing paged prefill this grew MALLOC_SMALL
      without bound: vmmap at ctx 8192 showed **80+ GiB dirty heap / 188K leaked
      ~412 KB allocations, footprint climbing ~1.3 GiB/5s -> jetsam "Killed: 9"**.
      This — NOT model residency — was the ctx>=8K OOM blocker; vmmap proved the
      GGUF mmap ("resident model 41.72 GiB" in the plan log) is only 6.3 GiB
      actually resident (demand-paged/clean). Fix: free+NULL cache_data[slot] on
      eviction. After fix: footprint plateaus ~5 GiB, MALLOC_SMALL flat ~2.4 GiB,
      a full paged prefill completes. Gate #5 re-run PASS bit-identical
      (max_abs_diff=0.0, 0/248320, resident sha==paged sha; frontier .logits.json

      to be confirmed by a post-fix 220K run. Source-only fix, no model artifact
      changed (HF upload rule N/A).
